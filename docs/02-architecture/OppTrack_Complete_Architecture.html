01 The premise

One writable field is the whole architecture

The workbook keeps a pipeline of design-win opportunities across six parallel tabs. Twenty-eight parameters are collected per row. Exactly four of them reach a currency figure: V1 EAU, V3 Distributor ASP, J1 Confidence Level and T1 quarterly units. Of those four, three are observations of the world. One — J1 — is a hand-entered opinion that multiplies every revenue number downstream of it.

So the agent's job is not to forecast revenue. It is to justify a deviation from a known baseline confidence, in percentage points, with a quote. Revenue is then recomputed by the same deterministic function that produced the base case, which is what makes the before and after comparable at all.

Sales Revenue and Adjusted Revenue are computed in code the model cannot reach. The judgment engine returns percentage points and quotations — never a figure.

That separation is what makes a number defensible when someone in a board review asks where it came from.

02 Parameter model

Twenty-eight live parameters, four of them load-bearing

Every parameter is registered by ID, never by spreadsheet column name. Validators, analyses and judge rules all declare which IDs they require; a module whose requirements are unmet stays dark rather than guessing. Adding a parameter activates the modules that declared a dependency on it.

IDParameterRoleReaches money?

U1 is correctly excluded from the revenue formula — EAU is already stated in chip units, so Unit/Set is an attach rate, not a missing multiplier. What remains is a validation problem rather than a schema one: the Funnel tab carries rows that do not reconcile with that definition (IP901 at 130,790 Kpcs over 4 per set implies 32.7M vehicle-sets a year, roughly a third of global light-vehicle production). That check lives in the rule engine at Layer 2, not in the calculation.

Five cross-tab joins do not exist. No two tabs share a key, so every relation between them is eyeballed rather than computed.

All five close with one field: a stable P0-1 Opportunity ID written on every row of every tab. It is first in the fix order because nothing else can be automated until it lands.

03 The boundary

Where the model is allowed, and what it may hand back

Requests only travel one way. Nothing in the data plane calls back up into a service, and no service calls a model except the judgment engine. Everything a reviewer reads as a currency figure was produced on the top lane below, two planes from any inference call.

What the model receives is the qualitative record for every row — status, stage, comments, competitor field, the raw V1/V3/V4 inputs — plus three computed share percentages per row that the concentration factor needs. It does not receive C1, C2, or any portfolio total. It cannot return one: the response schema has no field for it.

04 Calculation layer

Two lines of arithmetic, pinned to the workbook by test

calc_engine.py reimplements the ProjectTrack columns as plain Python with zero LLM involvement. test_calc_engine.py asserts it reproduces the sheet's own numbers exactly for all nine sample projects; if that test fails, the financial maths has changed, which should never happen silently.

IDFigureFormulaWorkbook origin
C1Sales revenueV1 × V3ProjectTrack O = K × M
C2Adjusted revenueC1 × J1ProjectTrack R = O × Q
C5Channel marginV4 − V3per unit
C8Regional roll-upΣ C1, Σ C2 by D1canonical regions
C9Stage roll-upΣ C1, Σ C2, count by L2funnel health
C12Concentrationrow C2 ÷ Σ C2by region, customer, OEM, SKU
T2Quarterly revenueT1 × V3FCST_Revenue S:V = L × N:Q

The invariant that matters: step 7 of a run re-executes this exact function against approved confidence values. The base case and the calibrated case are not two implementations that happen to agree — they are one function called twice, which is the only reason the delta between them means anything.

Effective portfolio confidence is ΣC2 ÷ ΣC1, and it is the number to watch across runs.

On the nine-row sample it starts at 0.375 — $82,350K unweighted, $30,915K weighted.

05 Matrix A

Baseline confidence is a table, not an inference

Design Status drives confidence; Stage independently checks it. A pairing marked forbidden is one the company's rules do not allow, and a row sitting on one is an internal contradiction the validator catches before any model runs. Baselines were inferred from the data and are the item awaiting ratification — ratifying this table is what turns the agent's job from inventing a confidence number into justifying a deviation from a known one.

Lifecycle bands

A confidence value falls in one of four bands. A proposal that would move a row across a band boundary does not auto-apply — it routes to a person. Everything inside a band applies on its own, which is the difference between a review queue and a rubber stamp.

BandRangeMeaning
terminal0.00 – 0.05Effectively lost
early0.05 – 0.45Promotion, Sample, Evaluation territory
designing0.45 – 0.85Design In, committed but not locked
locked0.85 – 1.00Design Win and Mass Production

Stage order is Concept → EVT → DVT → PVT → MP. Only Concept and EVT count as early. This is stated as config the model reads, not as prose it might interpret, because reading DVT as "early" was one of two misfires that accounted for 44% of the entire calibration effect on the first live run.

06 Matrix B

Thirteen factors, each with a cap and a direction

A factor may only fire when the row's own data supports it, and it must carry a verbatim quote from the bundle. Only J-03 and J-06 may return a positive adjustment; every other factor is a reduction or nothing. Factors whose input does not exist on this data return not assessable, which is the correct answer for them, not a failure.

Six of thirteen can fire on today's data. That is not a modelling shortfall — it is a data one. J-02 restores the moment Competitor Part# is copied onto ProjectTrack; J-06 and J-09 need an owner field and one quarter of retained history before they mean anything.

07 The call

One request, the whole pipeline, a schema on the wire

The judgment engine makes a single streaming call per run carrying every row at once — which is what lets J-05 concentration be computed at all, since it needs the portfolio to compare against. The reply shape is constrained server-side by a JSON schema on the request, not by an instruction in the prompt.

SettingValueWhy
Modelclaude-opus-5Hosted frontier API is primary; local vLLM is the residency fallback

Degradation ladder

Four request shapes are tried in order, and the shape actually used is recorded in provenance. Auth, permission, connection and not-found errors break out immediately rather than walking the ladder pointlessly. 

1 schema + thinking + server-side fallbacks   ← preferred
2 schema + thinking
3 schema only
4 plain                                      ← last rung; json_salvaged may be set

✕ every rung failed → raise JudgmentError. Never a silent mock.

A failed call raises. It never substitutes hard-coded numbers behind a successful-looking run.

The earlier prototype fell back to a rule-based MOCK scorer on any exception — and did, silently, when a markdown fence took out all nine projects on the first live run. Mode is now recorded per run and a failure is loud.

08 Guards

Eight ways a reply gets rejected, clipped or queued

validate_row() runs over every factor the model returned, in code, before anything reaches the recompute. Each rejection is recorded as a violation with a kind and a detail, so the audit record shows not only what applied but what was thrown away and why.

ViolationTriggerEffect
unknown_rulerule ID is not in the current rubric versionFactor discarded
not_assessablemodel set valid: falseFactor discarded, rationale kept
no_citationa factor applies with an empty evidence stringFactor discarded — no unexplained change
wrong_directionpositive adjustment from anything but J-03 or J-06Factor discarded
over_factor_cap|adjustment| exceeds that factor's capClipped to the cap, flagged
over_run_caprow total exceeds ±20pp in one runAll factors scaled proportionally
clampedresult falls outside [0.05, 0.95]Clamped, flagged
band_crossingentered and proposed sit in different bandsRouted to a human, does not auto-apply

The 0.95 ceiling matters more than it looks. The first implementation clamped to [0, 1], and both design wins in the sample already sat at 1.00 — so any positive support was discarded arithmetically and the layer could only ever move the portfolio down. A one-way haircut is not calibration. The band gives J-03 somewhere to put its points.

Structural, not policed: the service returns confidence only. There is no code path by which a model output becomes a revenue figure, so "no revenue writes" is impossible rather than forbidden.

09 One run

Ten steps, and the last two are not optional

A run never mutates its source, never writes confidence directly, and always terminates in a queue and a log. Steps 4 and 8 are architecturally present and deliberately not yet running — they depend on state history that does not exist, and the bench reports them as skipped rather than faking them.

  1. 01

    Intake

    Deterministic

    Read the snapshot. Record who owns each field. No interpretation.

  2. 02

    Validate

    Deterministic

    Gates V-a to V-i, including the Matrix A pairing check. Findings carry rule, severity and message.

  3. 03

    Compute the base case

    Deterministic

    C1 and C2 per row plus the roll-ups. These exist before any model call and are never replaced.

  4. 04

    Retrieve precedent

    JudgmentPhase 2

    pgvector over resolved opportunities. Nothing to retrieve until won/lost outcomes exist.

  5. 05

    Score the factors

    Judgment

    The one live model call. Whole pipeline, one request. Returns percentage points and quotes.

  6. 06

    Check the reply

    Deterministic

    Caps, citations, direction, per-run cap, clamp, band crossing. Violations are recorded, not swallowed.

  7. 07

    Recompute

    Deterministic

    The same arithmetic as step 3, on approved confidence. Same function, called twice.

  8. 08

    Lifecycle moves

    DeterministicPhase 2

    Promote to Mass Production, move to Design Lost, C14 time in stage. Needs state_history and a human gate.

  9. 09

    Human decision

    Person

    Only band-crossing rows queue. A reviewer clears them; nobody approves their own proposal.

  10. 10

    Log

    Deterministic

    Model ID, stop reason, token counts, rubric and prompt versions, rows moved, rows queued, decisions. Append-only.

The queue is the safety property.

Because the judge writes to a pending queue rather than to the record, a bad model run degrades to noise a reviewer dismisses — never to a wrong number in a board pack.

10 Code structure

Seven layers, one registry running through all of them

The structural decision everything else falls out of: a parameter registry is the single source of truth, and every layer declares which parameter IDs it needs rather than assuming they exist. Add a parameter and the modules that declared a dependency on it activate on their own — no hunting through code for what to switch on.

Three contracts worth pinning before features

Everything else can be refactored freely. These shapes are what keep the layers honest.

@dataclass(frozen=True)
class ParamSpec:                # the registry entry
    id: str                    # "V1", "J1", "L2" — never a column name
    name: str                  # "EAU"
    dtype: type
    unit: str | None           # "Kpcs", "USD", None

    required: bool

11 Deployment

Six planes, one direction of travel

Requests only ever move down. Nothing in the data plane calls back up into a service. The local inference box is sized for the same NVIDIA RTX PRO 6000 Blackwell workstation card (96GB VRAM) used by the sibling ROI Agent, since one card serves both.

OrchestrationExisting Workflow Manager routes "update pipeline" and "get weighted forecast"; mediates sibling-agent callsPlatform router · MCP tool schema

InferenceHosted frontier API primary; local fallback for data residency; embeddings on the same cardClaude · vLLM, Llama 3.3 70B 4-bit on 1× RTX PRO 6000 (96GB)

Model constraint applied throughout: non-Chinese models only. Local inference uses Llama 3.x, Mistral, Gemma or Command R+ — never Qwen or DeepSeek.

Sibling agents

The ROI Agent consumes this agent's Adjusted Revenue as its own revenue-forecast input, over MCP. The Semiconductor Design Agent sits on the same bus. Both share the inference card.

12 Data model

Ten tables, all hanging off one ID

The workbook keeps a pipeline in six parallel tabs with no shared key. Everything below hangs off a single opportunity row, which is what turns five eyeballed relations into real foreign keys.

Which is simultaneously stall detection, time in stage, velocity, win rate, and the outcome labels the calibration model needs later. None of those require new data collection — only a decision to stop overwriting.

13 Memory

Six tiers, and only one of them is a vector store

Agent memory usually gets collapsed into embeddings. Most of what this agent needs to remember is relational and exact: what state a project was in last month, who entered a number, what the rubric said at the time. Embeddings serve one tier out of six.

TierWritten byRead byAuthoritative for
L0 workingJudgment engine, in memoryNothing elseNothing. Never a source of truth
L1 episodicIntake, once per runAudit, reproduction, forecast vintageWhat the input actually was
L2 entityStage tracker, review consoleJudgment, analyses, dashboardCurrent state and how it got there
L3 semanticEmbedding job, after each ingestEvidence assembler onlyNothing. Supporting quotes only
L4 proceduralAdmin, through a published versionJudgment, validation, baseline lookupThe rules in force at a point in time
L5 calibrationQuarterly batch jobJudgment, as a priorHistoric bias, never a current number

L2 is the tier that makes this an agent rather than a calculator. A model with no memory re-derives the same opinion about the same project every month. With the dossier in front of it, it can observe that a project has sat at EVT for three quarters while its confidence stayed at 0.5 — a different and more useful statement.

Retention is a hard rule. L1 is immutable for seven years because it is the audit trail behind revenue figures shown to leadership. L3 rolls off after eight quarters, because stale precedent is worse than none. Deleting a person's account never deletes their decisions — it anonymises the display name, since removing the actor would break the audit chain.

14 Retrieval

Filter first, then search, and never embed a number

The evidence assembler pulls a fixed set of things for one opportunity, filtered before any similarity search runs, and hands over a bundle with a token budget. The model never queries the database itself. Region, product line and recency are applied as SQL predicates first, so the vector search only ranks candidates that were already relevant — similarity alone will happily return a Korean lighting socket as precedent for a European ADAS opportunity.

ContentChunkingWhy
Comments fieldOne chunk per row, per run vintageShort and self-contained; a note from 2024 should not read as current
Next action, status notesOne chunk, dates extracted separatelyMilestone dates are parsed into fields; only the prose is embedded
Loss write-upsOne chunk per closed opportunityThe highest-value precedent in the system once reason codes exist
Competitor notesOne chunk per part, per socketLets J-02 cite a specific prior encounter
Numbers of any kindNever embeddedA number recovered from a vector search is a number nobody can audit
Customer pricingNever embeddedRetrieval crosses region boundaries by design. Pricing must not

15 Identity

There is no public sign-up

This is an internal sales tool holding unreleased design wins and customer pricing. Accounts are provisioned by an administrator against a corporate directory, never self-registered, never shared between regional owners. Region scope is enforced in the query, not in the interface — hiding a region from a dropdown while the API still returns it is the failure mode worth designing out on day one.

RoleSeesMay doMay not
Regional sales ownerOwn region onlyCreate and update opportunities, supply evidence, request a reviewApprove a confidence change; close another region's record
Sales managerOwn region, all ownersApprove, reject or override a proposal; sign off on a closeEdit the rubric or the baseline table
Regional directorAll regionsEverything a manager can, plus cross-region roll-upsEdit an audit entry
FinanceAll regions, read onlyPull the forecast feed, run the ROI cross-checkChange confidence or move a record
AdminConfiguration, no pipeline data by defaultProvision users, set scopes, publish rubric versionsApprove a proposal
Service accountScoped to one connectorWrite provenanced field values from CRM, ERP or POSWrite confidence, move a record, or act as a person

Nobody approves their own proposal.

The agent proposes, an owner supplies evidence, a manager decides. Admin sits outside that loop entirely, so the person who can edit the rubric cannot also ratify the numbers it produces.

17 Current state

What is code today, and what is still a document

The POC directory holds a working vertical slice: the calculation layer, the judgment layer, the guards, and two browser benches that show every step's working. Everything else in this document exists as specification.

  judgment_bench.py     v2      Matrix A + 13 factors, schema, guards, no mock

judgment_bench.py is the rewrite that supersedes judgment.py. Six changes separate them, and each one traces to a specific failure on the first live run: Matrix A as config rather than prose, the 0.95 ceiling, whole-portfolio context so concentration can fire at all, a schema on the request, no silent mock, and caps enforced in code.

Running the benches

cd opptrack_poc
python run_poc.py            # end to end, before/after roll-up
python test_calc_engine.py   # regression against the workbook
python judgment_bench.py --serve   # judgment only, :8775
python opptrack_bench.py     # all ten steps, :8776

A judgement call scores nine rows across thirteen factors and takes a few minutes, so the bench server is threaded. ANTHROPIC_API_KEY is read from the environment, then from .env, then from a local key file; the page will also accept one pasted in.
