00 Conventions

How to read this

Every task carries a status, a phase and, where it matters, what blocks it. Sizes are engineering estimates for one developer and are mine, not committed — treat them as relative weights, not dates.

MarkMeans
DoneCode exists and is covered by a test. Only 5.1 and parts of 7.0 qualify today
PartialA working implementation exists in the POC or bench, but not in the shape the platform needs
To doNot started, and nothing prevents starting
BlockedWaiting on a decision, a field that does not exist, or history that has not accumulated
S M L XLRoughly: under a day, a few days, one to two weeks, longer
Phase 0–50 read-only, 1 numbers, 2 identity, 3 judgment, 4 learning, 5 outside-in

Ten tasks are blocked. Four of them clear the moment the four questions are answered.

Ratifying Matrix A, setting the confidence ceiling, deciding whether a person gates an auto-move, and confirming which workbook is current — those release 2.3, 2.4, 4.3 and 8.3, and unfreeze the tuning of 7.3. The remaining six wait on a field that does not exist, a licence, or history that has to accumulate, and no decision shortens those.

1.0 Package

Project control and stakeholder resolution

1.0 6 tasks · ongoing · releases 4 blocked tasks directly
Not engineering

This package exists because the largest remaining risk on the project is not technical. Four unanswered questions determine what the judgment layer is allowed to do; until they land, that code can be written but not tuned, and the numbers it produces cannot be defended in a review.

1.1
Send the four blocking questionsBlockedS

Q1 ratify the Matrix A baseline per valid (Design Status, Stage) cell. Q2 set the confidence ceiling — if a design win is not 1.00, what is the maximum any record may carry, and roughly how many points should dual sourcing or cancellation risk remove. Q3 does a person gate an auto-move to Mass Production or Design Lost. Q4 which workbook is current.

Q1 and Q2 are the expensive ones. Without Q1 the agent invents a confidence number rather than justifying a deviation from an agreed one, and the file itself contradicts the stage-driven rule: three Evaluation-at-EVT rows carry 0.30, 0.50 and 0.50. Without Q2 the clamp discards every positive adjustment, so the calibrated total can only ever move down.

Done when All four answered in writing and recorded in the open-questions register, with the Matrix A table signed off cell by cell.
unblocks 2.3, 2.4, 4.3, 7.3, 8.3 · owner: Akanksha

David refers to "the sheet I updated"; our copy still contains the Projection/Stretch block his does not. Validation rules get written against a specific file, so writing them against the wrong one wastes the whole of package 4.0. Low risk in itself — that block is the only stated difference — but it has to be settled before rules are authored.

Note while confirming: the #REF! roll-up rows are not pending fixes. They were broken deliberately when the forecast moved to a separate agent, and a validation rule that flags them as errors will produce noise on every run.

Done when One file is named as canonical, hashed, and stored as the Phase 0 fixture.

2.0 Package

Parameter registry and canonical model

2.0 6 tasks · Phase 0 · blocks most of what follows
Layer 1

The registry is the single source of truth every other layer declares against. Building it first is what makes the rest of the plan additive: adding a parameter later activates the validators, analyses and rubric factors that had declared a dependency on it, instead of requiring a hunt through the code for what to switch on.

2.1
ParamSpec for every parameterTo doM

One frozen dataclass per parameter: id, name, dtype, unit, enum, required, which tabs supply it, and whether it is present in the current file. Twenty-eight live entries plus the twenty-six proposed ones, so a proposed parameter is registered as absent rather than missing.

The rule that makes this worth doing: nothing downstream may reference a spreadsheet column name. Rules and analyses cite V1, never column K, so a sheet reshuffle is an intake change and not a codebase change.

Done when Every parameter in the dictionary has a spec, and a test asserts the registry covers every column the intake reads.
blocks 2.5, 3.6, 4.1, 6.1, 7.2
2.2
Canonical enumsTo doS

Region, design status, stage, product line, application and loss reason, each with its accepted variants. This is where KR becomes Korea and D-IN becomes Design In. It has to exist before the roll-ups are rebuilt, because a regional total computed over EU and Europe as separate keys is wrong in a way nobody notices.

Open item to resolve inside this task: the file holds EU, KR and North America, none of which appear on David's region list. Confirm the mapping, including whether North America means US only.

Done when Every enum value in the real file maps to exactly one canonical value, with no fallthrough.
blocks 3.4, 5.3
2.3
Matrix A as versioned configBlockedS

Valid pairings plus baseline confidence per cell, stored as a published version with an ID, not as a constant in a module. The bench already carries a proposed table; this task turns it into ratified, versioned configuration that a run records against every proposal it produces.

Also needs deciding here: whether MP is a legal Stage value at all, given the Stage column in the file holds only Concept, EVT, DVT and PVT.

Done when The table is published with a version ID and a run stamps that ID on every event.
blocked on 1.1 (Q1, Q2) · blocks 4.3, 7.3, 10.7
2.4
Opportunity ID scheme and backfill planBlockedM

The single highest-value item in the whole plan. Five cross-tab relations do not exist today because no two tabs share a key; all five close with one stable ID written on every row of every tab. This task covers the format, who issues it, and the one-time backfill of existing rows.

Cheap to build, awkward to agree, and nothing that depends on joining tabs can be automated until it lands. It should be treated as the project's first deliverable, not a schema detail.

Done when Every row in the canonical workbook carries an ID and the five joins are computed rather than eyeballed.
blocked on 1.1 (identity questions) · blocks 9.1, 9.2, 11.3
2.5
Registry-driven runnable()To doS

A single function that answers, for any module, whether the parameters it declared are present in the current snapshot. This is the mechanism behind the whole not-assessable behaviour: an analysis or rubric factor whose inputs are absent reports that it cannot run, rather than running on nulls and producing a confident number from nothing.

Done when Every analysis and rubric factor reports runnable or not, and the run output lists which are dark and why.
depends on 2.1 · blocks 6.1, 7.2
2.6
Reason-code vocabularyTo doS

Closed lists for loss reason, stage-exit reason and override reason. These are the labels the calibration model will eventually learn from, so a free-text field here costs a year: outcomes recorded as prose cannot be aggregated into owner bias without re-reading them by hand.

Done when The lists are agreed and enforced at the API, not just offered in a dropdown.
blocks 8.4, 6.5, 11.2

3.0 Package

Intake and normalisation

3.0 7 tasks · Phase 0 · no database, no auth, no model
Layer 2

Turns whatever arrives — a form submission, a CRM record, a workbook, an API call — into one canonical snapshot with provenance on every value. Nothing here interprets: coercion and canonicalisation only, so that a wrong value stays visibly wrong rather than being quietly repaired.

3.1
Workbook readerTo doM

Handles the two-row header on rows 3 and 4, and the shifted column letters on the terminal tabs. Reads six tabs into raw rows with no interpretation applied. This is import-path work, not the primary intake — direct entry is — but it is how the current book of business gets in and how Phase 0 demonstrates value before any platform exists.

Done when All six tabs read into raw rows with the header quirks handled and no silent column drift.
depends on 1.2 · blocks 4.5, 10.11
3.2
Snapshot writerTo doS

Write-once record of one run's input: sha256 of the source, source URI, row count per tab, timestamp. This is L1 episodic memory and the thing that makes a run reproducible — without it, "re-run last month" means re-reading a file that may have changed underneath you.

Done when A snapshot cannot be modified after sealing, and two runs over the same snapshot produce byte-identical calc output.
blocks 12.4, 9.7
3.3
CoercionTo doS

Dec'24 and June'27 to dates, TBD to null, thousands separators to float, percentages to fractions. The important behaviour is that TBD becomes null and is reported, not defaulted to zero — seven numeric fields in the current file carry TBD, and a zero there silently deflates a regional total.

Done when Every coercion is reversible to the source string, which is what the milestone factor must cite.
blocks 4.4, 6.3
3.4
CanonicalisationTo doS

Applies the enums from 2.2 to real values: KR to Korea, MOBIS to Mobis, D-IN to Design In, M/P to Mass Production. An unmapped value is a finding, never a new category invented at read time.

Done when The regional roll-up over the real file produces three regions, not five spellings of three regions.
depends on 2.2 · blocks 5.3
3.5
NRE line splitterTo doM

Seven of ten FCST_Revenue rows are non-recurring engineering charges sitting in the volume columns. They are not silicon revenue and must not be phased like it. This task lifts them into their own record type so C10 can recognise NRE by quarter separately from unit revenue.

Left unsplit, every quarterly revenue figure is inflated by one-off charges, and the error is invisible because the totals still tie to the sheet.

Done when Volume revenue and NRE reconcile separately to the workbook, and their sum ties to the original column.
blocks 5.4
3.6
Provenance wrapperTo doM

FieldValue(param, value, source, at, trust) on every value, from every path. This is what the Opportunities list renders as source badges, what the precedence ladder arbitrates over, and what lets a reviewer answer "who put that there" without opening a log.

Done when No value reaches the calc engine without a source and a trust level attached.
depends on 2.1 · blocks 10.4, 11.1, 11.2
3.7
Direct-entry intake serviceTo doM

The primary path, and the one the earlier documents under-specify because they all read the workbook. Accepts a single opportunity from the form or API, applies the same coercion, canonicalisation and validation as a bulk read, and captures owner, region and the confidence rationale at source. Values it writes carry the highest trust level, above every connector.

Done when A row created through the form is indistinguishable downstream from one imported, except that its provenance says a person entered it.
depends on 1.5, 3.3, 3.4, 3.6 · blocks 10.3

4.0 Package

Validation and findings engine

4.0 6 tasks · Phase 0 · the demo that needs no platform
Layer 2

The whole of Phase 0 is this package plus 3.0, and it already has something to say: on the current file, a company total that will not compute, seven TBD values in numeric fields, five skeleton rows carrying design wins worth zero, and a Funnel row implying a third of global light-vehicle production.

4.1
One rule per findingTo doL

Rules V-a through V-i, each declaring the parameters it requires so it goes dark rather than throwing when a field is absent. Rules are data-quality checks, not judgment: they answer whether the file is internally consistent, and every one of them must be explainable to a sales owner in a sentence.

Done when Each rule has a passing and a failing fixture drawn from the real file.
depends on 2.1, 1.2 · blocks 4.5
4.2
Blocking vs advisory severityTo doS

A blocking finding excludes the row from totals and counts it separately; an advisory one annotates and lets it through. The distinction matters more than it sounds: a design win worth zero silently included in a weighted total is how a forecast becomes wrong without anyone editing a number.

Done when Roll-ups report an included total, an excluded count, and never blend the two.
blocks 5.3, 10.2
4.3
Matrix A pairing checkBlockedS

Rejects, corrects or flags a row whose (Design Status, Stage) combination is forbidden. The check itself is a table lookup; what is undecided is the behaviour on failure, and that is a policy question, not an engineering one — rejecting at intake stops bad data entering, flagging lets a real edge case through with a warning.

Done when The agreed behaviour is implemented at both intake paths, form and import, identically.
blocked on 1.1 (Q1 and invalid-pairing policy) · depends on 2.3
4.4
Cross-tab contradiction checksTo doM

The two EAU definitions (ID801 reads 57,175 Kpcs on Funnel and 1,343 on FCST_Revenue), SoP dates that disagree across sheets, and totals that do not compute. These are the checks that most need the Opportunity ID from 2.4 — without a shared key they can only compare rows a human has paired up.

Done when Every contradiction in the current file is reproduced as a generated finding rather than a documented observation.
depends on 2.4, 3.3
4.5
Findings report rendererTo doM

The Phase 0 deliverable: the data-quality section of the specification, generated from the file instead of written by hand. Runs with no database, no auth and no model, which is what makes it demonstrable before any platform decision is made.

Done when All twelve documented findings are reproduced from the real workbook by running one command.
depends on 3.1, 4.1 · blocks 10.11
4.6
Dry-run validation for bulk importTo doM

Runs the full rule set against a proposed import and shows what would fail, before anything commits. Column mapping is confirmed by a person, the preview lists blocking and advisory findings per row, and nothing is written until the mapping is accepted.

Done when An import with a bad mapping can be abandoned with zero rows written and zero side effects.
depends on 4.1 · blocks 10.11

5.0 Package

Calculation engine

5.0 7 tasks · Phase 1 · partly built and regression-tested
5.1 done

Every currency figure a reviewer sees originates here, in plain Python with no model involvement. The invariant to protect throughout: the base case and the calibrated case must be the same function called twice, because that is the only reason the delta between them means anything.

5.1
C1, C2 and T2Done

Sales revenue as EAU times distributor ASP, adjusted revenue as sales revenue times confidence, and quarterly revenue as quarterly units times ASP. Implemented in calc_engine.py and asserted against the workbook's own numbers for all nine sample projects by test_calc_engine.py.

Done when Already met. The test is the contract: if it fails, the financial maths changed, and that should never happen silently.
—
5.2
C3 to C7To doM

Set volume, attach rate, channel margin in currency and percent, and part-level demand. None of these exist in the workbook; they are figures the sheet collects the inputs for and never computes. Channel margin in particular turns Resale ASP from a dead-end column into something that feeds an analysis and a rubric factor.

Done when Each has a regression assertion, and attach rate reconciles against the Unit/Set definition rather than contradicting it.
depends on 5.1
5.3
C8, C9 and C12 roll-upsPartialM

Regional roll-up rebuilt on canonical regions, stage roll-up by funnel stage, and concentration shares by every dimension at once: row, customer, end customer and part. A basic version exists in portfolio_rollup; this extends it to the full dimension set and to the exclusion behaviour from 4.2.

Concentration is the analysis with the most immediate value and the least new data. The current file already shows one project carrying 48% of the Korea pipeline, and no existing report says so.

Done when Roll-up totals tie to row-level sums and excluded rows are reported separately rather than dropped.
depends on 3.4, 4.2
5.4
C10 NRE recognition by quarterTo doM

Recognises non-recurring engineering separately from silicon volume, by quarter. Depends entirely on the splitter in 3.5; until that lands, every quarterly revenue figure carries one-off charges phased as though they were units.

Done when NRE and volume revenue are reported separately and sum to the workbook's original figure.
depends on 3.5
5.5
C11 quarterly phasing ruleBlockedM

How one annual EAU becomes quarterly revenue: flat across four quarters, a ramp from the M/P date, or driven by programme build data. Undecided, and it matters because automotive sockets run several years at varying volume while the ROI hand-off expects a year list.

Related open question to settle here: whether each opportunity needs a per-year volume profile rather than one annual figure. If it does, this is a schema change and not a formula.

Done when One rule is chosen, implemented, and its assumption stated on every export that uses it.
blocked on the phasing decision and 1.6
5.6
Extend the regression suiteTo doM

Every new output from 5.2 to 5.5 gets an assertion against the workbook or, where the workbook never computed it, against a hand-worked example checked by a second person. The existing test is the pattern; the discipline is that no calculation ships without one.

Done when The suite covers every C-number the product displays.
depends on 5.2–5.5 · rolls into 12.1
5.7
Scenario recompute serviceTo doS

Takes a set of confidence overrides and returns recomputed roll-ups without persisting anything. It backs the assistant's what-if answers, the review console's preview of an approval, and the rubric editor's impact estimate. One implementation, three consumers, which is what stops those three disagreeing in front of a customer.

Done when A scenario call leaves no trace in the database and returns the same numbers a real approval would produce.
depends on 5.3 · blocks 10.5, 10.7, 14.3

6.0 Package

Analysis registry

6.0 6 tasks · Phase 1 · six live today, two blocked upstream
Layer 4

Analyses are deterministic reports over the computed figures. They are separated from the judgment layer deliberately: an analysis states a fact about the portfolio, a rubric factor argues about a confidence level, and conflating the two is how a report becomes an opinion.

6.1
Analysis protocol and registryTo doS

A protocol with a requires declaration, and a registry that discovers modules and decides which may run against the current snapshot. Same mechanism as 2.5, applied to analyses: the run output should list what ran, what was dark, and which parameter was missing.

Done when Adding an analysis module requires no registration code, only a requires declaration.
depends on 2.1, 2.5
6.2
Six live analysesTo doL

Stage mix and pipeline health, concentration risk, contradiction and data quality, milestone and stall detection, competitive exposure, and channel margin. All six run on today's data. Stage mix answers whether the weighted total is top-heavy with Concept-stage optimism; concentration answers what a single loss would cost.

Done when Each produces a figure a reviewer can act on, not a chart, and each names the rows it is talking about.
depends on 5.3, 6.1
6.3
Milestone extractorTo doM

Pulls PPAP, ES, Design Review and SoP dates out of the Funnel prose into real date fields, then flags what is overdue or missing an action. The parsed date goes into a field; the source string is kept, because the rubric factor that cites a slip must quote what was written, never the parse.

Done when Every date the extractor claims can be traced back to the exact substring it came from.
depends on 3.3 · blocks 7.2 (J-10)
6.4
Coverage against targetBlockedS

Compares weighted pipeline against a regional target to answer whether there is enough in the funnel. Blocked because no targets are defined anywhere in the file or the documents; the analysis is trivial once a number exists to compare against.

Done when Targets exist per region and per period, and coverage is reported against them.
blocked: targets undefined
6.5
Forecast accuracy and owner calibrationBlockedL

Compares what was forecast against what shipped, per region and per owner, producing the bias figures that become L5 memory. Blocked twice over: no actuals are connected, and no owner field exists anywhere in the workbook. Needs two quarters of retained history before it says anything trustworthy.

This is the task that eventually makes the agent better rather than merely consistent, and it is worth starting the clock on early — the data has to accumulate before the analysis can be written.

Done when Owner bias is computed from resolved outcomes and fed to the judgment layer as a prior, never as a current number.
blocked on 2.6, 9.2, 11.4 and two quarters of history
6.6
Run-to-run comparisonTo doM

Diffs two snapshots and attributes every change to a cause: a person edited a field, a connector wrote a value, a proposal was approved, or the rubric version changed. This is what makes the director's view answer "why is the number different from last month" without anyone reconstructing it by hand.

Done when Every delta between two runs is attributable to a recorded event, with no unexplained residual.
depends on 3.2, 8.2 · supports 12.4

7.0 Package

Judgment layer

7.0 9 tasks · Phase 3 · largely prototyped in judgment_bench.py
Mostly partial

The only layer that touches a model, and the one with the most existing work. The bench already implements Matrix A as config, the thirteen factors, the schema on the request, the guards and the provenance block. What remains is turning a bench into a service, and connecting the factors that currently cannot fire.

7.1
score_confidence service signaturePartialM

Wrap the bench as score_confidence(opportunity, portfolio_context, rubric_version) returning a proposal rather than applying one. The portfolio context argument is not optional: under the original one-row signature the concentration factor could never fire at all, because it had nothing to compare a row against.

Done when The service returns a proposal object, writes nothing, and the concentration factor fires on the Korea case.
depends on 1.4 · blocks 8.1
7.2
Matrix B as declaring rulesPartialM

Each of the thirteen factors declares the parameters it requires and its cap, so a factor whose input is absent returns not-assessable instead of guessing. Six can fire on today's data; the correct behaviour for the other seven is to say so, and that is a property of the design rather than a gap in it.

Done when Every factor reports runnable or not, and no factor produces an adjustment from a null field.
depends on 2.1, 2.5
7.3
Rewrite J-01 and J-04 against Matrix APartialS

The two misfires that between them accounted for 44% of the entire calibration effect on the first live run: J-01 docked Aphrodite for a Design In at DVT pairing the rules allow, and J-04 read DVT as an early stage. Both are fixed by giving the model the table and the stage order as config rather than expecting it to infer them from prose.

Done when Aphrodite and Montana no longer misfire, asserted as explicit negative fixtures.
depends on 2.3 · tuning blocked on 1.1
7.4
ConfidenceProposal contractPartialS

A typed contract with the bounds asserted at construction: rule ID drawn from the current rubric, signed adjustment within the factor cap, non-empty evidence, and a validity flag. Asserting in the constructor rather than checking later means an invalid proposal cannot exist as an object, let alone reach a reviewer.

Done when Constructing an out-of-bounds proposal raises, and the guards cannot be bypassed by a caller.
depends on 7.2
7.5
Evidence assemblerTo doL

Filters by region, product line, part and recency as SQL predicates first, then ranks by similarity, then applies a token budget. The order is the point: similarity alone will happily return a Korean lighting socket as precedent for a European ADAS opportunity, and the filter is what stops it. The model never queries the store itself.

Two rules enforced inside the assembler: numbers of any kind are never embedded, and customer pricing is never embedded — retrieval crosses region boundaries by design, and pricing must not.

Done when A bundle is bounded, reproducible for a given snapshot, and contains no figure the calc engine produced.
depends on 9.3 · content blocked until outcomes resolve
7.6
Model clientDone

JSON schema on the request rather than an instruction in the prompt, stop_reason checked before parsing, text block located by type, a four-rung degradation ladder, and a loud failure. Implemented in judgment_bench.py. The rule it enforces: a failed call raises and never substitutes hard-coded numbers behind a successful-looking run.

Done when Already met in the bench. Carries into the service unchanged.
—
7.7
Print the written reasonsPartialS

Run output must carry the model's rationale and its quote, not only factor names and deltas. A reviewer cannot calibrate their trust in a layer that only ever shows them arithmetic, and the quote is the thing that makes a wrong factor obviously wrong at a glance.

Done when Every factor on every output surface carries its evidence string verbatim.
depends on 7.4 · blocks 10.5
7.8
Prompt and rubric versioningDone

Model ID, prompt version, rubric version, request shape, schema-enforced flag and token counts stored per event. This is what lets two runs be compared rather than argued about, and it is already in the bench's provenance block.

Done when Already met. Must survive the move into the service unchanged.
feeds 8.2, 6.6
7.9
Unblock J-02 and J-07BlockedS

Copying Competitor Part# onto the tracked row restores the named-competitor factor immediately — the single cheapest unblock in the plan. Dual sourcing needs the same column plus the note field. Both are data-model changes, not modelling work.

Done when Both factors fire on a real row and cite the competitor part string.
blocked on the competitor column reaching the tracked row

8.0 Package

Review, audit and lifecycle

8.0 7 tasks · Phase 3 · the safety property of the whole design
Human in the loop

Because the judge writes to a pending queue rather than to the record, a bad model run degrades to noise a reviewer dismisses rather than a wrong number in a board pack. Everything in this package exists to keep that true.

8.1
Proposal queue and human gateTo doL

Approve, reject, override with a value, or mark needs-follow-up. Only rows whose proposal crosses a lifecycle band queue; everything else applies automatically, which is the difference between a review queue and a rubber stamp. Nobody may decide their own proposal, checked in code against the actor rather than hidden in the interface.

Done when All four outcomes write an audit row, and an owner attempting to approve their own row is refused by the API, not by a missing button.
depends on 7.1, 9.5 · blocks 10.5
8.2
Append-only confidence_event writerTo doM

Every proposal and every override, with actor, role, scope, model ID and both version stamps, written before the decision returns. Rejections are logged too — they are the calibration signal, and a log that only records accepted proposals cannot answer whether the layer was worth running.

Done when No mutation path exists that can change or delete an event, for any role including admin.
depends on 1.4, 9.1 · feeds 6.6, 12.4
8.3
Auto-move to Mass Production or Design LostBlockedM

Step 8 of a run. The mechanics are simple; the policy is not. Read together with auto-entered confidence, the answers given so far mean nobody signs off before an opportunity is closed as lost, and those two answers were given separately — which is exactly the kind of gap the open-questions register exists to catch.

Done when The agreed gate is implemented, and a close cannot happen without whatever sign-off the policy requires.
blocked on 1.1 (Q3) · depends on 9.2
8.4
Mandatory loss reason at closeTo doS

A closed-list reason code required on the way out, enforced at the API. Cheap to build, and it is the single field that makes loss write-ups worth embedding later — without it, precedent retrieval has nothing to retrieve and the calibration model has no labels.

Done when No opportunity can reach a terminal state without a reason code from the agreed vocabulary.
depends on 2.6
8.5
Stall and milestone alertingTo doM

Nightly sweeps that flag anything sitting in one stage beyond its historic median, and any parsed PPAP, ES or SoP date now past due. The alert carries the rationale, not just the flag: days in stage against the median, or the source string the date came from.

Done when An alert can be acted on without opening the record to work out why it fired.
depends on 6.3, 9.2
8.6
Deterministic recompute on approvalTo doS

Approving a proposal re-runs the calc engine over the approved confidence. No second model call, no cached figure from the proposal. This is the task that keeps the base case and the calibrated case the same function called twice, and it should be asserted, not assumed.

Done when The post-approval figure is byte-identical to running the calc engine directly on the approved value.
depends on 5.7, 8.1
8.7
Reviewer feedback captureTo doS

When a reviewer rejects or overrides, capture why against a closed list plus optional prose. This is the fastest available signal on whether the rubric is calibrated, and it arrives months before any won-lost outcome does. — Sequencing

Critical path, and what to do first

Two chains carry most of the schedule risk, and they are both short. Neither is difficult engineering; both are waiting on a decision or a field.

ChainSequenceGates
Identity chain 1.1 → 2.4 → 9.1 → 9.2 → 9.8 Every cross-tab join, four rubric factors, two analyses, and the whole of Phase 4
Judgment chain 1.1 → 2.3 → 7.3 → 8.1 → 10.5 Whether a proposal is defensible; whether positive adjustments are possible at all

Start the Opportunity ID and state_history now, ahead of anything else.

Neither needs new data collection, and both accumulate value with time rather than on delivery: the event stream is worthless the day it ships and indispensable two quarters later. Every month spent overwriting Design Status is a month of calibration data that cannot be recovered.
