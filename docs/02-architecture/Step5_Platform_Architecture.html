01 SCOPE

What this document decides

Step 2 named the technologies. It did not say how an account gets created, what a row in the database looks like, what the agent remembers between runs, or how evidence reaches the model. Those four gaps are what stop this being buildable, and they are what follows.

Two rules run through all of it. First, the agent writes exactly one field, Confidence Level, and every currency figure is computed by plain Python that no model can reach. Second, a run is a pure function of a snapshot: the same input reproduces the same numbers, and anything the model contributed is recorded with the prompt version and model ID that produced it.

02 FIG. A  ·  SYSTEM CONTEXT

Six planes, one direction of travel

Requests only ever move down. Nothing in the data plane calls back up into a service, and no service calls a model except the judgment engine.

03 FIG. B  ·  IDENTITY AND ACCESS

There is no public sign-up

This is an internal sales tool holding unreleased design wins and customer pricing. Accounts are provisioned by an administrator against a corporate directory, never self-registered, and never shared between regional owners.

ROLES AND WHAT EACH ONE MAY DO
RoleSeesMay doMay not
Regional sales ownerOwn region onlyCreate and update opportunities, supply evidence, request a reviewApprove a confidence change, close another region's record
Sales managerOwn region, all ownersApprove, reject or override a proposal, sign off on a closeEdit the rubric or the baseline table

Nobody approves their own proposal. The agent proposes, an owner supplies evidence, a manager decides. Admin sits outside that loop entirely, so the person who can edit the rubric cannot also ratify the numbers it produces.

04 FIG. C  ·  DATA MODEL

Ten tables, all hanging off one ID

The workbook keeps a pipeline in six parallel tabs with no shared key. Everything below hangs off a single opportunity row, which is what turns five eyeballed relations into real foreign keys.

05 FIG. D  ·  MEMORY

Six tiers, and only one of them is a vector store

"Agent memory" usually gets collapsed into embeddings. Most of what this agent needs to remember is relational and exact: what state a project was in last month, who entered a number, what the rubric said at the time. Embeddings serve one tier out of six.

WHO WRITES EACH TIER, AND WHO MAY READ IT
TierWritten byRead byAuthoritative for
L0 workingJudgment engine, in memoryNothing elseNothing. Never a source of truth
L1 episodicIntake, once per runAudit, reproduction, forecast vintageWhat the input actually was
L2 entityStage tracker, review consoleJudgment, analyses, dashboardCurrent state and how it got there
L3 semanticEmbedding job, after each ingestEvidence assembler onlyNothing. Supporting quotes only
L4 proceduralAdmin, through a published versionJudgment, validation, baseline lookupThe rules in force at a point in time
L5 calibrationQuarterly batch jobJudgment, as a priorHistoric bias, never a current number

Retention has a hard rule. L1 is immutable for seven years because it is the audit trail behind revenue figures shown to leadership. L3 rolls off after eight quarters because stale precedent is worse than none. Deleting a person's account never deletes their decisions, it only anonymises the display name, since removing the actor would break the audit chain.

06 FIG. E  ·  RETRIEVAL

How evidence reaches the model

Retrieval here is narrow by design. The assembler pulls a fixed set of things for one opportunity, filtered before any similarity search runs, and hands over a bundle with a token budget. The model never queries the database itself.

WHAT GETS EMBEDDED, AND WHAT DOES NOT
ContentChunkingWhy
Comments fieldOne chunk per row, per run vintageShort and self-contained. Vintage matters, since a note from 2024 should not read as current
Next action and status notesOne chunk, dates extracted separatelyMilestone dates are parsed into fields. Only the prose is embedded
Loss write-upsOne chunk per closed opportunityThe highest-value precedent in the system once reason codes exist
Competitor notesOne chunk per part, per socketLets the competitor rule cite a specific prior encounter
Numbers of any kindNever embeddedEAU, ASP and confidence are read from columns. A number recovered from a vector search is a number nobody can audit
Customer pricingNever embeddedRetrieval crosses region boundaries by design. Pricing must not
